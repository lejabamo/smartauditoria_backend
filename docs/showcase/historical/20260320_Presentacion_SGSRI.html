Definición Estratégica

Problema y Propósito del Sistema

Problemática en Entidades Públicas

  • Inventarios Dispersos: Activos de información gestionados manualmente en hojas de cálculo desactualizadas.
  • Valoración Subjetiva: Evaluaciones de impacto y probabilidad sin criterios unificados ni respaldo técnico.
  • Brecha Normativa: Desconexión entre el inventario tecnológico y los requerimientos DAFP V7 y MIPG.

Propósito de SmartAuditorIA

  • Centralización: Gobierno estructurado de activos con clasificación de Confidencialidad, Integridad y Disponibilidad (CIA).
  • Asistencia Inteligente: Sugerencia de controles ISO/IEC 27002 contextualizados a las amenazas evaluadas.
  • Generación Oficial: Matrices dinámicas 5x5 y reportes listos para auditorías institucionales de control interno.
Ingeniería de Software

Arquitectura y Repositorios GitHub

Ecosistema modular desacoplado en tres repositorios oficiales independientes:

  • Backend API: Python Flask, SQLAlchemy, base de datos MariaDB y seguridad JWT.

Motor Inteligente & Seguridad

  • Engine IA (RAG): FastAPI, pipeline de recuperación contextual y catálogo ISO 27002.
    github.com/lejabamo/smartauditoria_engine
  • Infraestructura: Proxy inverso Nginx con SSL Let's Encrypt sobre servidor VPS OVH Cloud.
Alcance Funcional

Las Cinco Épicas del Proyecto

1. Gestión de Activos

Inventario, categorización (Software, Hardware, Datos) y cálculo de criticidad CIA según lineamientos DAFP V7.

2. Matriz de Riesgos ISO

Cálculo automático de riesgo inherente y residual (Probabilidad × Impacto) con mapa de calor 5x5 (ISO 27005).

3. Motor Inteligente RAG

Recuperación aumentada por contexto para sugerencia asistida de controles ISO/IEC 27002:2022.

4. Dashboard y 5. Despliegue

Monitoreo de criticidad institucional, exportación de reportes y despliegue robusto con HTTPS en la nube.

Cierre Académico

Limitaciones y Próximos Pasos

Limitaciones Técnicas Actuales

  • La base de conocimiento RAG actual opera en modo estructurado; la base vectorial requiere persistencia dedicada.
  • La ingesta de activos opera mediante carga estructurada; la integración GLPI requiere configuración de webhooks.

Próximos Pasos para la Tesis

  • Despliegue del cluster de ChromaDB con embeddings densos en servidor dedicado.
  • Batería formal de evaluación cuantitativa con framework RAGAS.
  • Automatización del pipeline de CI/CD vía GitHub Actions para despliegue sin intervención manual.
