1. Qué Funcionó (Fortalezas y Logros Verificados)

Resultados técnicos consolidados durante los Sprints 1 y 2 en el entorno de desarrollo y producción:

Backend y Datos (Flask API + MariaDB)

  • Modelo Relacional de Activos: Estructuración completa de tablas para activos, clasificaciones CIA y autenticación con roles RBAC (ADMIN, OPERADOR, CONSULTOR).
  • Motor de Criticidad: Algoritmo de cálculo de impacto y probabilidad alineado con el marco DAFP V7 y MIPG.
  • Seguridad de Acceso: Autenticación JWT con expiración controlada y bloqueo preventivo anti-fuerza bruta tras 5 intentos fallidos.

Frontend y Despliegue en la Nube

  • Wizard de Auditoría: Flujo paso a paso con validaciones por etapa que guía la identificación y valoración de riesgos.
  • Matriz 5x5 Dinámica: Cuadrícula visual de calor para mapeo de severidad de riesgo inherente y residual (ISO 27005).
  • Despliegue Cloud en Producción: Servidor VPS OVH Cloud (IP 51.79.35.88) operativo bajo dominio institucional seguro: https://riesgosti.tics.sedcauca.gov.co.

2. Qué Dificultades se Presentaron (Retos Reales)

Obstáculos técnicos y operativos identificados durante la ejecución:

  • Ausencia de Sincronización Automática en Jira: El backlog y las historias de usuario (SCRUM-12 al SCRUM-35) se administran en Jira Software (smartauditoria.atlassian.net/.../summary), pero no se cuenta con integración automática mediante webhooks hacia los repositorios de GitHub, demandando actualización manual de estados.
  • Compatibilidad de Dependencias de IA: Conflictos entre versiones de Python y librerías de embeddings (ChromaDB / PyTorch) en servidores virtuales con recursos de memoria RAM restringidos.
  • Estructuración Normativa ISO 27002:2022: Complejidad para representar los 93 controles de ciberseguridad en un esquema uniforme que permita su consulta sin generar alucinaciones en el modelo LLM.
  • Carga Operativa en Trabajo Individual: La ejecución simultánea de actividades de infraestructura Linux/Nginx, programación React/Flask y documentación académica requirió priorizar estrictamente el alcance para cumplir los hitos de entrega.

3. Qué Aprendimos (Lecciones Clave)

  • Pruebas de Integración E2E como Criterio de Verificación: La automatización de pruebas sobre el entorno de producción (mediante scripts como test_production.py) garantiza la estabilidad del sistema antes de introducir nuevas capas de abstracción.
  • Desacoplamiento Estricto de Repositorios: La separación en tres repositorios independientes (Frontend, Backend y Engine IA) permitió versionar, probar y desplegar componentes sin generar dependencias cruzadas en el código fuente.
  • Estrategia Espiral en Sistemas de IA: Validar primero el flujo de usuario con sugerencias estructuradas (RAG v1) permitió asegurar la experiencia de auditoría antes de desplegar infraestructuras vectoriales complejas (RAG v2 con ChromaDB).

4. Qué Acciones de Mejora se Proponen

Compromisos para el siguiente ciclo y la consolidación de la Tesis de Maestría:

  • Acción 1 (Base Vectorial Persistente): Desplegar ChromaDB con almacenamiento permanente en el servidor dedicado para indexar los 93 controles de la norma ISO/IEC 27002:2022.
  • Acción 2 (Evaluación Cuantitativa con RAGAS): Implementar una batería de pruebas objetivas que mida precisión, fidelidad de contexto y relevancia en las recomendaciones de control.
  • Acción 3 (Automatización CI/CD y Webhook Jira): Configurar el pipeline en GitHub Actions para despliegue automatizado vía SSH e investigar la conexión formal de webhooks con Jira Software.
  • Acción 4 (Conector GLPI): Desarrollar el servicio de ingesta periódica para sincronizar activos de TI directamente desde la base de datos de mesa de ayuda.

5. Cómo se Comprobará Cada Mejora (Criterios y Métricas)

Matriz de verificación objetiva para el siguiente hito académico:

Acción Propuesta Métrica Cuantitativa Objetivo Método de Validación
1. Base Vectorial ChromaDB Tiempo de recuperación < 250 ms sobre los 93 controles ISO 27002. Pruebas de carga sintética en smartauditoria_engine.
2. Métricas RAGAS Puntaje de Faithfulness > 0.85 y Context Precision > 0.80. Ejecución automatizada de evaluación cuantitativa para el informe de tesis.
