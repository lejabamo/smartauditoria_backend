Diapositiva 1 de 10 • Marco Institucional y Problema

Contexto Institucional, Problema y Alcance Normativo

  • Programa Académico: Maestría en Computación para el Desarrollo de Aplicaciones Inteligentes — Universidad del Valle (Trabajo Integrador 2, Ing. Leonardo Javier Bastidas Moreno).
  • Problema Abordado: En entidades públicas territoriales (caso Secretaría de Educación y Cultura / Gobernación del Cauca), el levantamiento de activos de información, la valoración de riesgos y el cruce contra los 93 controles de ISO/IEC 27002:2022 se realizaban en hojas de cálculo aisladas (.xlsm), sin trazabilidad forense ni asistencia experta para justificar la aplicabilidad normativa.
  • Solución Implementada (SmartAuditorIA — SGSRI): Plataforma web desacoplada con asistencia híbrida de Inteligencia Artificial (RAG + CAG + Fallback Determinístico), alineada con ISO/IEC 27001:2022, ISO/IEC 27002:2022 (93 controles), ISO/IEC 27005, Guía DAFP V7 / MIPG y Ley 1712 de 2014.
Evidencia Navegable: EP-06 (SCRUM-43) HU-021 (SCRUM-38 Identidad Cauca) App Producción VPS (Login) Healthcheck API VPS (HTTP 200)
Diapositiva 2 de 10 • Arquitectura de Software

Arquitectura Desacoplada en Tres Repositorios Oficiales

  • Frontend (smartauditoria_frontend): SPA/PWA en React 18 + TypeScript + Vite con Matriz 5x5 interactiva, Wizard conversacional con chips Human-In-The-Loop, Panel SoA de 93 controles y módulo administrativo RBAC.
  • Backend Transaccional (smartauditoria_backend): API REST Flask + SQLAlchemy + MariaDB 10.11 bajo arquitectura limpia (domain/, application/, routes/) para inventario DAFP V7 Cap. V, cálculo $RI = P \times I$, SoA y exportación Excel del Mapa Oficial de Riesgos.
  • Engine IA (smartauditoria_engine): Microservicio FastAPI + ChromaDB (chroma.sqlite3) + SentenceTransformers (all-MiniLM-L6-v2) + Google Gemini API para recuperación semántica y generación asistida (RAG/CAG).
  • Decisión Arquitectónica: Aislar el motor IA en su propio servicio permite mantener el núcleo transaccional del SGSRI disponible al 100% incluso ante latencias del LLM externo o ausencia de cobertura en la base vectorial.
Evidencia Navegable: HU-003 (SCRUM-12 Docker) backend/953426d Repo Backend Repo Frontend Repo Engine IA

Diapositiva 8 de 10 • Validación Experimental del Motor IA (RAG/CAG)

Validación de IA: Métricas Reales, Limitaciones Identificadas y Decisiones de Mejora

  • Métricas Reales del Benchmark Vectorial Reproducible (chroma.sqlite3 + all-MiniLM-L6-v2):
    • Cobertura Normativa en Vector Store: La colección langchain contiene 85 chunks de ISO_27001_2022_Espa_.pdf.pdf (Anexo A resumido), cubriendo 32 de los 93 controles ISO/IEC 27002:2022 (34,4%); 61 controles (65,6%) no están en el archivo SQLite vectorial.
    • Desempeño en 5 Casos de Prueba (TC-RAG-01 a TC-RAG-05): Precision@3 Promedio = 0,1333 (13,3%) (aciertos en TC-RAG-02 [A.8.28, P@3=0,33] y TC-RAG-03 [A.7.10, P@3=0,33]; 0,00 en los otros 3 casos por ausencia del control o vecindad léxica) | Latencia $p_{50} = 13,60\text{ ms}$ | Latencia $p_{95} = 161,68\text{ ms}$ | Fallos = 0,0% | 35 tests unitarios/integración aprobados en smartauditoria_engine/tests.
  • Limitaciones Reconocidas con Transparencia Académica: (1) El PDF ingerido en ChromaDB fue la norma ISO 27001 (resumen Anexo A) y no la guía extensa ISO 27002:2022 completa; (2) No está instalada la librería Python ragas para evaluar automáticamente con juez LLM la fidelidad generativa (Faithfulness) de Gemini en CI/CD.
  • Decisiones Arquitectónicas Implementadas y Plan V4.0:
    • Mitigación en Producción: Fallback Determinístico (HU-103 / SCRUM-31) sobre el catálogo JSON completo de 93 controles (iso_27002_2022_catalog.json) cuando el score RAG es bajo, más validación Human-In-The-Loop (HU-202 / SCRUM-33) en el Wizard.
    • Corrección Estructural en V4.0: Re-indexar los 93 controles completos en ChromaDB para superar P@3 >= 0,70 (HU-028 / SCRUM-46) e integrar la suite Python ragas en GitHub Actions (HU-029 / SCRUM-47).
