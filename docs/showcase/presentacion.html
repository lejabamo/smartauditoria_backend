2. Arquitectura Desacoplada en Tres Repositorios Oficiales

  • Frontend (smartauditoria_frontend): SPA/PWA en React 18 + TypeScript + Vite con identidad institucional Gobernación del Cauca / GOV.CO.
  • Backend Transaccional (smartauditoria_backend): API REST Flask + SQLAlchemy + MariaDB 10.11 para inventario de activos, cálculo de riesgos, SoA de 93 controles, RBAC y reportes DAFP V7.
  • Engine IA (smartauditoria_engine): Microservicio FastAPI + ChromaDB + SentenceTransformers (all-MiniLM-L6-v2) + Google Gemini API para recuperación semántica y generación contextual (RAG/CAG).
  • Decisión Arquitectónica: El aislamiento del motor IA en un contenedor independiente evita que la carga de memoria de embeddings o la latencia del LLM bloqueen las operaciones transaccionales del SGSRI.

9. Decisiones Técnicas Derivadas de las Pruebas y Suite de 111 Tests Locales

  • Decisión Técnica 1 — Fallback Determinístico sobre el Catálogo Maestro de 93 Controles (SCRUM-31): El resultado experimental (Precision@3 = 13,3% por cobertura vectorial del 34,4%) demuestra por qué la arquitectura no depende exclusivamente de ChromaDB: cuando el score semántico es inferior al umbral (0,75) o falta un control en el vector store, iso_suggestions_service.py y gemini_cag_service.py activan el fallback determinístico sobre el catálogo JSON completo de 93 controles (iso_27002_2022_catalog.json).
  • Decisión Técnica 2 — Validación Human-In-The-Loop (SCRUM-33): El componente ConversationalAuditor.tsx presenta chips de acción interactivos para que el auditor humano apruebe o descarte cada control sugerido antes de persistirlo.
  • Ejecución Real de las 111 Pruebas Automatizadas Locales (100% Pass):
    • Backend (pytest smartauditoria_backend/tests): 45 passed, 0 failed en 8,14 s (12 archivos unitarios y de integración).
